**belay v0.1.0-alpha.4 is a pre-alpha.** It records what changed in a directory and explains it. It
changes nothing, undoes nothing, and contains nothing. Use it to look, not to protect.

## What changed since v0.1.0-alpha.3

**Version 1 protect specs are now refused.** If yours says `"belay_protect": 1`, change it to `"belay_protect": 2`, and export any baseline made with it again.

- `no_write` now also forbids deleting a path: deleting is a write to the file's existence. Replaying 2,115 published agent runs found two that deleted a file they were told not to write, and belay said nothing.
- `no_delete` alone still forbids deleting and allows writing.
- `protected_path_deleted`'s text is now `{path}: protected by {rule}, removed`.
- A bundle exported with a version 1 spec must be exported again; a bundle with no spec is unaffected.
- An entry marked `writer_open` is never folded under a git-ignored directory: it is listed by name.

The manifest format is unchanged: version 4, as in v0.1.0-alpha.3.

## What it still can't see

A protect spec sees files, not intent: a hack that lives in code it does not protect passes, and it reports that a protected file changed, not why.

The limits on a concurrent writer are as v0.1.0-alpha.3's notes state them, in full:
- **Where it can't ask:** on macOS, on filesystems without leases, and for files belay's user does not own without `CAP_LEASE`, belay can't ask. On overlayfs, a shared mapping whose descriptor was closed is invisible. A torn hash there still diffs as an ordinary change; each manifest says only how many files were hashed this way, as `unguarded`.
- **A fast writer:** one that opens, writes and closes entirely between the two checks, within one timestamp tick, is seen by nothing.
- **A writer on another machine:** on a filesystem that grants leases locally, it may go unseen. This is unverified.

As in earlier releases: no undo and no sandbox -- belay records and reports and is not a security boundary.

## Files

| file | platform |
|---|---|
| `belay-v0.1.0-alpha.4-linux-x86_64` | Linux, x86_64; statically linked |
| `belay-v0.1.0-alpha.4-linux-arm64` | Linux, arm64; statically linked |
| `belay-v0.1.0-alpha.4-macos-arm64` | macOS 15, Apple silicon; links only the system library; not notarized |
| `SHA256SUMS` | the sha256 of each binary |
| pybelay wheels, `WHEELS-SHA256SUMS` | the Python bindings, version 0.1.0a4, with each wheel's sha256 |

Each binary was built from the tagged commit by the release workflow, and run end to end before it
was attached. To verify one:

```sh
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify belay-v0.1.0-alpha.4-linux-x86_64 --repo Allexsen/belay
```

On macOS the binary is not notarized: remove the quarantine attribute
(`xattr -d com.apple.quarantine belay-v0.1.0-alpha.4-macos-arm64`) or build from source.

## Status

Pre-alpha: interfaces, output and formats may change without notice. No stable API. The most useful contribution is real-world use: if belay missed a change, invented one, or buried the real one in noise, [open a mismatch issue](https://github.com/Allexsen/belay/issues/new?template=mismatch.yml). Security reports: [SECURITY.md](https://github.com/Allexsen/belay/blob/v0.1.0-alpha.4/SECURITY.md). Apache-2.0.
