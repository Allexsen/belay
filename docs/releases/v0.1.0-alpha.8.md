**belay v0.1.0-alpha.8 is a pre-alpha.** It records what changed in a directory and explains it. It
changes nothing, undoes nothing, and contains nothing. Use it to look, not to protect.

## What changed since v0.1.0-alpha.7

**`belay watch`: a running record of a directory while an agent works in it.**

- `belay watch step` records what changed since the last step and prints one line: anything in a sensitive place, or matching your `.belay-donttouch`, first behind a red circle; the rest counted. `mark` and `summary` give a turn's totals; `receipt` prints every change of every step, nothing folded; `patterns` shows what each pattern matches now.

  ```
  belay: 🔴 .git/hooks/pre-push added (git hook) · 7 more: 7 added (5 under node_modules/)
  belay: .git/config modified (git config) · 2 more: 2 modified
  belay: 8 changed this turn in 1 tool call · full receipt: /belay:receipt
  ```

- What it says and when is pinned in [test/expect/watch-v1.md](https://github.com/Allexsen/belay/blob/v0.1.0-alpha.8/test/expect/watch-v1.md): the lines, a built-in list of 66 rows (each with what was run to check its tool honours it, or marked not verified), and the measurement behind the list. Over 27 install, scaffold, build and test steps, 2 lead with a red circle (a `.pth` file added to `site-packages` each time); over 14 git operations, 4 do and 3 more are noted without one.
- **It catches careless changes**: what an agent, a tool it ran or an install did without saying. It does not hold against a process running as you that attacks belay's state, its lock or its commands.
- **Always a line, never silence.** A step runs under a deadline of 45 s. When it cannot record, a line says so and why, the next step covers the same interval, and the summary repeats it. A step is never said to be lost after it was recorded.

**A Claude Code plugin**, a thin wrapper around `belay hook claude-code`:

```
claude plugin marketplace add Allexsen/belay
claude plugin install belay@belay
```

One line after every tool call that changed something, the turn's totals when the agent stops, and `/belay:receipt` for everything. The wrapper fetches this release's binary once and runs it only if its sha256 is the pinned one. See [claude-plugin/README.md](https://github.com/Allexsen/belay/blob/main/claude-plugin/README.md).

**`belay prune`**

- Where `belay watch` keeps a record, the checkpoint its next step reads is never removed, and a day of the record goes once no checkpoint its lines name is left ([state-retention-watch.md](https://github.com/Allexsen/belay/blob/v0.1.0-alpha.8/test/expect/state-retention-watch.md)).
- `--watch-only` removes only checkpoints a watch step wrote. It is the form the plugin runs, once a day: the plugin never removes a checkpoint you made.
- **Fixed:** a prune killed while it rewrote a checkpoint left a file that made every later prune stop with "holds what belay did not write" (exit 4).

**Other fixes**

- A JSON number too large for 64 bits was converted in a way C leaves undefined (found by fuzzing). It is clamped.
- `belay diff` in a git repository with nothing tracked, or nothing ignored, sorted an empty list in a way C leaves undefined.

**Unchanged:** the manifest (version 4), diff.v1, policy.v1, the protect spec (version 2) and the baseline bundle. The protect spec's pattern rules are as before; the matcher is now shared with `belay watch`, whose lists also match names that start with a dot. `belay log` shows `, watch` on a checkpoint a watch step wrote.

**Known limits of `belay watch` and the plugin**

- A fetched binary found damaged at a session's start is removed and said so, and is fetched again only at the next session's start.
- A subagent's tool call that never finishes stays open for as long as its parent session goes on, so later changes are counted under it.
- When calls of a session that died are closed by an event that makes no step, the line that says so is not printed.
- A binary that hangs is silent until Claude Code's hook timeout ends the hook.
- A change made and undone between two steps is not seen; a file caught half written can be counted in two steps, as the two states it was in.
- A modified `.git/config` is noted whatever key changed: `core.hooksPath` like `user.name`.
- Rows for tools that could not be run here (26 of 66: CI systems, editors, direnv, cargo, yarn 2, Cursor, Copilot) are included by name and marked not verified.
- macOS: built and tested in CI; the plugin has not been tried there by hand.

## What it still can't see

A protect spec sees files, not intent: a hack that lives in code it does not protect passes, and it reports that a protected file changed, not why.

The limits on a concurrent writer are as v0.1.0-alpha.3's notes state them, in full:
- **Where it can't ask:** on macOS, on filesystems without leases, and for files belay's user does not own without `CAP_LEASE`, belay can't ask. On overlayfs, a shared mapping whose descriptor was closed is invisible. A torn hash there still diffs as an ordinary change; each manifest says only how many files were hashed this way, as `unguarded`.
- **A fast writer:** one that opens, writes and closes entirely between the two checks, within one timestamp tick, is seen by nothing.
- **A writer on another machine:** on a filesystem that grants leases locally, it may go unseen. This is unverified.

As in earlier releases: no undo and no sandbox -- belay records and reports and is not a security boundary.

## Files

| file | platform |
|---|---|
| `belay-v0.1.0-alpha.8-linux-x86_64` | Linux, x86_64; statically linked |
| `belay-v0.1.0-alpha.8-linux-arm64` | Linux, arm64; statically linked |
| `belay-v0.1.0-alpha.8-macos-arm64` | macOS 15, Apple silicon; links only the system library; not notarized |
| `SHA256SUMS` | the sha256 of each binary |
| pybelay wheels, `WHEELS-SHA256SUMS` | the Python bindings, version 0.1.0a8, with each wheel's sha256 |

Each binary was built from the tagged commit by the release workflow, and run end to end before it
was attached. To verify one:

```sh
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify belay-v0.1.0-alpha.8-linux-x86_64 --repo Allexsen/belay
```

On macOS the binary is not notarized: remove the quarantine attribute
(`xattr -d com.apple.quarantine belay-v0.1.0-alpha.8-macos-arm64`) or build from source.

## Status

Pre-alpha: interfaces, output and formats may change without notice. No stable API. The most useful contribution is real-world use: if belay missed a change, invented one, or buried the real one in noise, [open a mismatch issue](https://github.com/Allexsen/belay/issues/new?template=mismatch.yml). Security reports: [SECURITY.md](https://github.com/Allexsen/belay/blob/v0.1.0-alpha.8/SECURITY.md). Apache-2.0.
