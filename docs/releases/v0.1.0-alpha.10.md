**belay v0.1.0-alpha.10 is a pre-alpha.** It records what changed in a directory and explains it. It
changes nothing, undoes nothing, and contains nothing. Use it to look, not to protect.

## What changed since v0.1.0-alpha.9

**More kinds of change are explained, in every scope.**

- Seven new interpreters say what a change to a system file means, as written in the file: users and groups (`etc/passwd`, `etc/group`), sudo rules, cron jobs with their schedule in words where it can be told without guessing, systemd units, timers and init scripts, the key lines of `authorized_keys`, the certificates of the trust store, and the keys of nginx, sshd and ini-style configuration files.
- They claim files by path, so they run wherever such a file is in the scope: a `--docker` container, a project that carries an `etc/`, or a system watch. A container's diff can now say `user deploy added: uid 1002` or `sudo rule added in etc/sudoers.d/deploy: deploy ALL=(ALL) NOPASSWD:ALL`.
- They state the file's text, never its effect. A file they cannot read as its grammar says is reported as `could not interpret`, not skipped.
- **Not established by a run:** the configuration grammars have been run against belay's own fixtures, not yet against `nginx -t`, `sshd -T` or `systemd-analyze`.
- dpkg's events gain `auto`: whether apt marks the package as installed automatically.
- **diff.v1 gains event kinds and one trailer key.** The trailer ends with `runtime`, 0 outside a system watch. A reader that rejects unknown keys or kinds, pybelay before this release included, needs this release.

**git: a pull is told from a rewrite.**

- **Fixed:** a merge made by `git pull --no-rebase` was flagged as rewritten history. The operation is now matched as git writes it, not as a substring. Also fixed: `pull (finish)` under `pull.rebase` and `pull -r` were counted as commits added, a rewrite missed; a commit whose subject held `forced-update`, and `pull --rebase` that fast-forwarded, were flagged as rewrites.

**`belay watch` and the Claude Code plugin: what a first session says.**

- A pull or a merge leads the step's line: `belay: git pull: main moved to 40b8714 (fast-forward) · 17 changes in the tree: 3 added, 2 removed, 12 modified`, in place of a count that included everything under `.git/`. It appears for a repository at the top of the watched directory.
- The watch receipt folds what git wrote under `.git/` into one line, as `belay diff` does. An entry that a line flags or notes, a hook or `.git/config` among them, is always listed. `belay watch receipt --all` folds nothing.
- The plugin says `belay: recording ~/proj` when a session starts in a directory it records.
- Started from the home directory, it says why it does not record and what to do: `not watching ~ (your home directory): too wide. Start Claude Code in a project directory to record it.`, and `belay: not recording: ~ is too wide` at each stop. **Fixed:** `/belay:receipt` there answered that nothing had changed.

**`belay watch --system`: a whole machine, experimental.**

- Reads the roots of `/` that hold a machine's configuration (content for `etc`, `usr/local`, `root`, cron, dpkg's database and each home's keys, startup files and user units; metadata only for `usr`, `var`, `opt`), with a record of what is listening and which services run, and a receipt in sections: installed, services, listening, user, cron, sudo, ssh, setuid, secret, trust, config. With `--docker C` it reads a container's `/` from the host.
- **It is slow on a large machine.** On a hosted Ubuntu 24.04 runner with 1.05 million entries the first capture took 20 minutes, a step 40 to 75 seconds, the receipt about 2 minutes and 300 MB. There is no kernel record in this version: every capture is a walk, and a change made and put back between two captures is not seen.
- Its output and its state may change. `verify`, `--protect` and `baseline export` refuse a system watch.

**Captures of large trees.**

- The record of the previous capture is kept on disk beside the state, not in memory, and a capture's delta is written as a stream. A tree of two million entries is captured within 64 MiB of memory.

**Smaller changes.**

- A file that could not be read is reported on its own line with `content not read`, and such rows never fold into a count.
- A protect rule of `no_delete` alone reads existence only: a protected file that is present but unreadable is not unverifiable under it.
- `belay prune --docker` takes a container that is running or paused; it took only a paused one.

**Changed formats.** The manifest is version 5 (versions 1 to 4 are read). A checkpoint's record gains keys. State written by this release is not read by v0.1.0-alpha.9: an older binary on it fails and says so at every step, and its `verify` refuses a bundle this release exported. The protect spec (version 2) is unchanged. The baseline bundle's own format is unchanged; the manifest it carries is version 5.
