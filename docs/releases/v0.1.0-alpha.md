**belay v0.1.0-alpha is a pre-alpha.** It records what changed in a directory and explains it. It
changes nothing, undoes nothing, and contains nothing. Use it to look, not to protect.

## What is in this release

- `belay check`, `mark`, `diff` and `log` ([docs/cli.md](https://github.com/Allexsen/belay/blob/v0.1.0-alpha/docs/cli.md)):
  record a directory as a checkpoint, record what changed since the last one (reading only files
  that may have changed), show the difference as a receipt or as JSON, list checkpoints. No
  privileges needed; belay reads the directory it is given and writes only under its own state
  directory (`~/.local/state/belay` by default).
- Explanations of changes to pip installs, dpkg's package database, git refs, hooks and reflogs,
  and small text files. Anything else is reported by hash, size and metadata.
- The manifest format version 2: the format belay intends to keep reading. The diff format
  (diff.v1) is a draft and may still change.

## Files

| file | platform |
|---|---|
| `belay-v0.1.0-alpha-linux-x86_64` | Linux, x86_64; statically linked |
| `belay-v0.1.0-alpha-linux-arm64` | Linux, arm64; statically linked |
| `belay-v0.1.0-alpha-macos-arm64` | macOS 15, Apple silicon; links only the system library; not notarized |
| `SHA256SUMS` | the sha256 of each binary |

Each binary was built from the tagged commit by the release workflow, and run end to end before it
was attached. To verify one:

```sh
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify belay-v0.1.0-alpha-linux-x86_64 --repo Allexsen/belay
```

On macOS the binary is not notarized: remove the quarantine attribute
(`xattr -d com.apple.quarantine belay-v0.1.0-alpha-macos-arm64`) or build from source.

## What it does not do, and what it does not see

- **No undo, no sandbox.** belay records and reports. It is not a security boundary, and nothing
  here stops a process from doing anything.
- **Live trees.** belay reads a directory that may be changing. An entry that changed while it was
  read is flagged (`raced`, `unstable`, `vanished`) and reported as unknown, never as unchanged; a
  receipt counts them and says that running belay again settles them. Some writes cannot be seen
  while they happen (a file changed only through a shared memory mapping on overlayfs, for one);
  the limits are listed in the manifest specification.
- **Coarse timestamps.** `mark` skips files whose metadata shows they cannot have changed. On
  filesystems with 1- or 2-second timestamps it is more conservative and reads more; a `check`
  always reads every file.
- **Your own user.** A process running as your user while a capture runs could redirect what
  belay writes in its state directory. That is outside belay's threat model: such a process can
  already change anything you can.
- **Not seen:** anything outside the directory given, anything below a mount point inside it,
  belay's own state directory (left out, and said), and anything that is not a file: network
  effects, pushes, API calls, emails.
- **Not explained:** git objects and packs, the git index (seen as changed, not explained),
  reflogs over 16 MiB, text files over 64 KiB, and every format belay has no interpreter for.

## Status

Pre-alpha: interfaces, output and formats other than the manifest may change without notice. No
packages, no Python bindings, no stable API. Bugs: the issue tracker. Security reports:
[SECURITY.md](https://github.com/Allexsen/belay/blob/v0.1.0-alpha/SECURITY.md). Apache-2.0.
