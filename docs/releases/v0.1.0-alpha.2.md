**belay v0.1.0-alpha.2 is a pre-alpha.** It records what changed in a directory and explains it. It
changes nothing, undoes nothing, and contains nothing. Use it to look, not to protect.

## What changed since v0.1.0-alpha

**git, explained at the level of the repository.** A diff now says what happened to a repository,
not only which of its files changed: a branch created, deleted, renamed or moved, commits added to
it, its history rewritten (a reset, an amend, a rebase, a forced update), HEAD switched or detached.
The values come from the refs themselves; the reflog only says how a branch moved, and only when it
agrees with the refs -- it is written by the process being watched, so what it says is evidence,
not proof. A ref that raced while it was read still gives its event, marked provisional; what
cannot be read narrows what is claimed (a branch "now at" a commit) rather than dropping it. Tags
and remote-tracking refs are reported file by file, as before.

**Excluded paths, named in the diff itself.** diff.v1's header now carries each side's excluded
paths (`before_excluded`, `after_excluded`), so a consumer of the JSON sees what was not compared
without reading standard error. A path that one side did not capture (excluded, below an unreadable
directory, below a mount) derives no package event: excluding a virtualenv no longer reads as
packages installed or removed.

**Excludes, stricter and safer.**
- `belay exclude --add` refuses an exclude that would make a manifest's header line too long to
  read back, and a capture refuses to write such a header (exit 4) rather than leave an unreadable
  manifest.
- An `excludes` file holding a NUL, a control character or a line twice is corrupt state (exit 4).
- `--remove` of a path that is not excluded is an error (exit 2).
- belay's own state directory takes one excluded slot however many bind mounts show it inside the
  scope; a second appearance is recorded as the mount it is.

**Behaviour changes.**
- An option given twice (`--scope`, `--since`, `--to`, `--add`, `--remove`) is a usage error
  (exit 2); before, the last one won.
- The receipt's first section is headed `events` (it was "packages and files explained"): it now
  holds git's events as well as packages'.
- diff.v1 (still a draft) gains header keys and event kinds; a consumer ignores kinds it does not
  know (diff-events E8).

The manifest format is unchanged: version 2, as in v0.1.0-alpha.

## Files

| file | platform |
|---|---|
| `belay-v0.1.0-alpha.2-linux-x86_64` | Linux, x86_64; statically linked |
| `belay-v0.1.0-alpha.2-linux-arm64` | Linux, arm64; statically linked |
| `belay-v0.1.0-alpha.2-macos-arm64` | macOS 15, Apple silicon; links only the system library; not notarized |
| `SHA256SUMS` | the sha256 of each binary |

Each binary was built from the tagged commit by the release workflow, and run end to end before it
was attached. To verify one:

```sh
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify belay-v0.1.0-alpha.2-linux-x86_64 --repo Allexsen/belay
```

On macOS the binary is not notarized: remove the quarantine attribute
(`xattr -d com.apple.quarantine belay-v0.1.0-alpha.2-macos-arm64`) or build from source.

## What it does not do, and what it does not see

As in v0.1.0-alpha (its notes list the limits in full): no undo and no sandbox -- belay records and
reports and is not a security boundary; a live tree is read as it changes, and what changed while
it was read is reported unknown, never unchanged; nothing outside the directory given, below a mount
point inside it, in belay's own state directory or in a path you exclude is seen, and each of those
is named; git objects and packs are not read, and the reflog is the watched process's own account.

## Status

Pre-alpha: interfaces, output and formats other than the manifest may change without notice. No
packages, no Python bindings, no stable API. Bugs: the issue tracker. Security reports:
[SECURITY.md](https://github.com/Allexsen/belay/blob/v0.1.0-alpha.2/SECURITY.md). Apache-2.0.
