# belay audit — 2026-10-20 (M0)

Maps every component in BELAY_DESIGN.md §5 to **exists / partial / missing**, with file references.
Baseline commit: `eab9b64`. Build: `make` succeeds (2 warnings, both `main`'s unused `argc`/`argv`).
Runtime: `./bin/belay` **fails** — `mount overlay failed on mnt`, `EINVAL` (see §Known-broken).

## Summary

Everything that exists belongs to **capture/C (session engine)**, which the new design places at
**M4** — behind M1 (checkpoint engine), M2 (integrity/policy) and M3 (host reader + RL demo).
Of 17 §5 components, **1 is partial, 16 are missing**. There is no CLI, no diff code, no
interpreters, no tests, no CI, no schema, no public headers.

Total source: **728 lines** across 13 files in `src/`.

**C, in detail — what actually works:**

- `src/session.c` — XDG state resolution (`$XDG_STATE_HOME` → `$HOME/.local/state` fallback),
  `mkdtemp` session naming, layout creation (`upper/ work/ temproot/`), path join helpers.
  Verified by running.
- `src/fork.c` — `pipe2(O_CLOEXEC)` → `fork()` → child: `unshare(CLONE_NEWUSER|CLONE_NEWNS)`,
  deny `setgroups`, identity uid/gid maps, `MS_REC|MS_PRIVATE`; parent: reads the pipe, `waitpid`,
  propagates exit code. Verified.
- `src/rootfs.c` — per-top-level-directory overlays (`construct_temproot`, `make_entry_dirs`,
  `mount_entry_overlay`, `clone_symlink`), and `switch_root` (`pivot_root(".",".")` +
  `umount2(".", MNT_DETACH)`). **Overlay mounting verified working by strace** for every top-level
  directory that contains no nested mounts.
- `src/childerr.c` — child→parent failure protocol: stage enum + `_Static_assert`-checked name
  table, fixed-size `struct child_err` in one sub-`PIPE_BUF` write, four distinct parent read
  outcomes.
- `src/utils.c` — `mkdir_p`, `contains`.
- `src/mounts.h` — **declarations only**; `src/mounts.c` is **0 bytes**. `mounts_load` and
  `mounts_has_nested` are unimplemented.

**C, what is missing** (design §5.5): `commit`, `discard`, `snapshot`, `branch`, `reset`;
guard/contain modes; passthrough list; locked masks; network profiles; 3-way commit check;
copy-up cost reporting; escapes in receipt. Steps 6–7 of the fork sequence are partial —
`pivot_root` works, but `/proc` `/dev` `/sys` are **skipped and never remounted**
(`STAGE_REMOUNT_PROC` exists in the enum with no call site), so the forked shell has no `/proc`.

## Known-broken

1. **`./bin/belay` fails at runtime.** `mount_entry_overlay` returns `EINVAL` on `/mnt`; `dmesg`:
   `overlayfs: failed to clone lowerpath`. Cause: `/mnt` contains 7 nested mounts (WSL's 9p and
   tmpfs Windows-interop mounts). This is the case `binpash/try` documents at `try:288`.
   Agreed fix (not yet written): detect nested mounts via `/proc/self/mountinfo`, bind-mount those
   directories **read-only** so writes fail with `EROFS` rather than silently escaping capture.
   `src/mounts.c` was created for this and is empty. **This is M4 work and no longer blocking.**
2. **No `/proc` in the fork.** `/proc` `/dev` `/sys` are excluded from the walk and never remounted,
   so anything in the forked shell reading `/proc` breaks. Design step 7.
3. **`/bin/bash` hardcoded**, should be `$SHELL`. `TODO(fork)` at the `execl` site carries the
   login-shell (`-` prefix) trap.
4. **Diagnostic `printf`s** in `construct_temproot` go to the child's stdout and are lost unless
   `stdbuf -o0` is used, because `child_fail` calls `_exit()` and skips flushing.
5. **`src/rootfs.c` relies on a transitive include** for `AT_SYMLINK_NOFOLLOW`; `<fcntl.h>` is not
   included explicitly.

## Reusable against the new milestones

- **`src/utils.c`** — `mkdir_p`, `contains`: usable anywhere.
- **`src/session.c`** — XDG resolution and path joining: reusable by the checkpoint engine for its
  manifest/step store location.
- **The failure protocol** (`src/childerr.c`) — specific to the fork's child/parent split; not
  reusable by the unprivileged engines.
- **The Makefile** — needs `include/`, `test/` and per-platform targets for §9.1 CI.
- **Portability:** everything in `src/` is Linux-specific by nature (`unshare`, `mount`,
  `pivot_root`). M1 requires `capture/A`, `diff/` and `interp/` to be **portable POSIX C building on
  macOS in CI** — so M1 shares almost no code with what exists.

## What M1 needs that does not exist

Per §9, M1 is: `check`/`diff`/`mark` working unprivileged in a plain dir and in Docker;
interpreters pip, dpkg, git, text, binary; `diff.v1` schema drafted; portable POSIX C passing tests
on macOS in CI.

Required and absent: a CLI/dispatch layer, manifest format and writer, manifest reader and
comparator, hashing, a step store, the five interpreters, the JSON schema, a JSON writer, a test
harness, and CI config. **M1 is a greenfield build**; the existing session-engine code is
orthogonal to it.
