# Pin: the kernel record (fanotify)

**Status.** Approved by the author, 2026-11-19, after two independent reviews. The code follows in later
PRs: until a row's code has merged, nothing in it is implemented, and `docs/cli.md` says only what is.
Rows marked **owed** state what a run must show before the code resting on them merges.

**Evidence.** "Measured" means run on GitHub-hosted Ubuntu 24.04 (kernel 7.0) and 22.04 (kernel 6.8)
runners, 2026-11-18 and 19. The file names and section labels given (`events.txt` E1, `facts.txt` P4,
`owed.txt` U1, `round-3`, ...) are those runs' outputs, kept in the project's notes, not in this repository.

**What this is.** What belay records from the kernel while a system watch runs as root, when a
capture may rest on it, and what it never claims from it. Every "measured" row is from
`ev-ubuntu-24.04/events.txt` (kernel 7.0) and
`ev-ubuntu-22.04/events.txt` (kernel 6.8), ext4, unless it names another file.

**Changing it.** In its own PR, presented as a table, after the author's explicit OK.

## The recorder

| id | rule | how established |
|---|---|---|
| K1 | `belay watch start --system`, run as root, starts one recorder process per watch. It ends at `watch stop`, or when its state directory is removed. One fanotify group: `FAN_CLASS_NOTIF`, `FAN_REPORT_DFID_NAME`, `FAN_REPORT_FID`, `FAN_REPORT_TARGET_FID`, the default queue. Events: `FAN_MODIFY`, `FAN_CLOSE_WRITE`, `FAN_ATTRIB`, `FAN_CREATE`, `FAN_DELETE`, `FAN_RENAME`, with `FAN_ONDIR`. | measured: accepted on 6.8 and 7.0 (E0) |
| K2 | One `FAN_MARK_FILESYSTEM` for every filesystem the capture enters under the roots (manifest-v5 V5-E6) whose type is on K2a's list, and one for the state directory's when it is not among them. The recorder keeps a descriptor open on each marked filesystem's root directory. | measured: with it held, `umount` fails busy; after a lazy unmount and a mount elsewhere events still arrive (E4) |
| K2a | **Marked, and on the events basis: `ext4` only.** Every other entered filesystem (`btrfs`, `zfs`, `xfs`, `vfat`, `f2fs`, `ext2`, `ext3`) is walked at every capture, and the receipt's `kernel record` line names it: `walked every time: var/lib/data (btrfs)`. A type joins this list by a run of this pin's cases on it, with the author's OK. A capture that includes such a walk is under watch-system WS-3a's limit like any walk. When no entered filesystem is ext4 the kernel record is off: `off: no ext4 filesystem under the roots`. | measured: every case of this pin was run on ext4, on two kernels. btrfs: one inode number names different files in the top volume and in a subvolume (`self=[ino 257 /mnt/b/top]` and `self=[ino 257 /mnt/b/sv/insub]`, E5), so `(dev, ino)` from an event does not name a file there. ZFS: a child dataset's write resolved to the dataset's root, not the file (`owed-*/owed.txt`, Z1). xfs, vfat, f2fs: not run |
| K3 | A filesystem not entered (manifest-v5 V5-E6: remote, stacked, in-memory, any type not listed there) is a `mount` entry and is neither marked nor walked. | measured: overlayfs refuses the mark, `Operation not supported` (E5, E7) |
| K4 | A recorder that cannot start turns the kernel record off for the watch, with the kernel's message. The cases known: not root, and root in a container without `CAP_SYS_ADMIN` (`fanotify_init`: `Operation not permitted`); a container with `CAP_SYS_ADMIN` or privileged (the mark on `/`: `Operation not supported`, overlayfs); a btrfs subvolume mounted by itself (`Invalid cross-device link`). A mark refused later, for a filesystem mounted under a root while the watch runs, leaves the record on and puts that filesystem among those walked every time. | measured: E5, E7; `facts.txt` P8 for the ordinary user |
| K5 | The journal is `<state>/watch/journal.<n>`, appended in batches, each segment with a fanotify ignore mark on its own inode; a new segment begins at each checkpoint's barrier. One line per event: `seq`, `time_ns`, `mask`, `dev`, `ino` of the object, and for a named event `dir_dev`, `dir_ino`, `name` (base64 when not UTF-8); for a rename both names. `dev` and `ino` are `st_dev` and `st_ino` from a stat of the object opened by its handle at record time; an object that no longer opens has `ino: null`. No path is resolved and none is filtered at record time. Segments older than the oldest checkpoint of the watch are removed by `prune`. | measured: with the ignore mark, 2 of 587 lines named the journal (E2); without one, most of 574,000 (`round-3/README.md`) |
| K6 | The recorder polls `/proc/self/mountinfo` and journals `mounts_changed` when a mount appears or goes at or below a directory the capture enters, or over one; other changes of the table (a container's overlay, `/run/user/<uid>`) are not journaled. It journals `overflow` when the kernel reports one. Reading the queue never stops for a walk: walks run in another process (watch-system WS-3a). At start it sets and clears the immutable flag on a file of its own in the state directory and journals whether an event came: `iflags_events: true \| false`; a filesystem that refuses the flag reads as `false`. | measured: the poll woke on mount and unmount (E4); `OVERFLOW` arrived when the reader was stopped for 40,000 creates, and not in a 128,613-event install (E3); `chattr` gave `A` on 7.0 and nothing on 6.8 (E1) |

## Captures

| id | rule | how established |
|---|---|---|
| K7 | **The barrier**, taken while holding the state's lock and before the capture looks at anything: belay creates and unlinks `<state>/watch/barrier.<random>` and waits (5 s at most) until the recorder has journaled that create. The events before it are this capture's; later ones are the next one's. The checkpoint records the barrier's `seq` (`journal_seq`, checkpoint-v3) and the manifest's `walk_start_ns` is the barrier file's `ctime_ns` as the filesystem gave it: for an event capture that is the reference the next capture's trust rule uses, on the same clock file times come from. No barrier in time: the capture is a walk, reason `the recorder did not answer`. | measured: 8,042 events from two directories on 7.0 and 5,712 on 6.8, none after the sentinel (`facts.txt` P8) |
| K8 | **The dirty set.** From the journal between the previous barrier and this one: every object the previous manifest has an entry for (by `dev`, `ino`), and every directory it has an entry for in which a name was created, deleted or renamed, unless that entry is `not_read` or the path is excluded (belay's state directory is: its own writes are never dirt). An event for an object the manifest does not have, in a directory it does not have, is not dirt. Plus: every inode under a root that some process has open for writing or mapped shared and writable, found by `stat` of `/proc/<pid>/fd/*` (with `fdinfo`'s `flags` for the access mode) and of `/proc/<pid>/map_files/*`; every entry the previous manifest flags `raced`, `unstable` or `writer_open`; every path in its trailer's `racy`. An object the manifest has is dirty even when its entry is a `not_read` directory (its mode and owner are compared); only its listing is never taken. | measured: a write through a mapping gives no event until the descriptor and the mapping are both gone, then one `W`; `fdinfo` shows `flags: 02100002`; `stat -L` of `map_files/*` gives the file's own device and inode (`64512 1474`) (E1) |
| K9 | **An event capture** (`basis: "events"`). The roots are resolved again first (a home's `.ssh` may be new): a root that appeared is walked, one that went is dropped. Then for each dirty object, every name the previous manifest has for it is statted and looked at by its class; each dirty directory's listing is taken again, and a directory that arrived by create or rename is walked. Every other entry is carried. Its reads and writes are bounded by the dirty set and the index lookups: it neither reads nor rewrites the previous manifest, and is stored as a delta of version 2, named by its identity and not by a digest of bytes it never had (state-retention ST-1, ST-3, ST-4). The step that follows it takes its diff and its flags from the dirty entries alone, the old ones from the index and the new ones from the capture: no manifest is rebuilt for it. Owed before merge: a step with 100 dirty paths on the 1.13 M-entry image, in seconds; over 5 s comes back to the author. A dirty directory whose search bit for others changed, or that arrived by rename, has its whole subtree looked at again, because the class of what is below may have changed (manifest-v5 V5-E5); and an entry is carried or trusted only when the class the rules give it now is the one it has in the previous manifest. | measured: modify, attribute, create, delete and rename events carry the object's inode; replacing or unlinking one name of a two-name file sends `A` for the inode; a directory rename carries old and new names (E1). A hard link to a file of `/etc` made in `/var/tmp`: the link's creation, a write and a chmod through the outside name each carry the inode of the file in `/etc` (`ino 1474`, `ino 1369`), on both kernels (`recheck2-*/recheck.txt`) |
| K10 | An event capture is taken only when all of these hold; otherwise the capture is a walk (`basis: "walk"`) and the checkpoint's `full_reason` says which failed: the recorder that journaled the previous barrier is still the one running, in the same boot; no `overflow` and no `mounts_changed` since; every event's object resolved (`ino` not null) or its directory did; the limits, claims and excluded paths equal the previous capture's; every `stored` the previous manifest names is in the store; the state's sealing key is the previous manifest's; the previous capture was a walk or an event capture of this watch; fewer than `--full-every` captures since the last walk (default 20). | the conditions are the first review's F10, F12 and the second pass's M5, M10; unresolvable events measured in the overlay cases (E6: `Stale file handle`) |
| K11 | A capture whose dirty set is empty and whose resolved roots are unchanged writes no checkpoint. The step's line is the one for nothing changed. This holds only when no entered filesystem is walked every time (K2a), or when that walk finds every entry as the previous manifest has it: what the walk finds is part of the capture like any dirt. | follows from K8: belay's own writes and events outside the manifest are not dirt |
| K12 | `watch receipt` and `watch stop` take a walk, whatever the journal says. The receipt's `end state` line gives its time. | design: the end state never rests on events alone |
| K13 | **`touched`.** A regular file read on both sides (`sha256` on both, `sealed` included) with equal `size` and hash, for whose inode the journal has a `FAN_MODIFY` between the two checkpoints' `journal_seq`: the event record `{"event": "touched", "interp": "core", "text": "written and now as it was", "paths": [...]}`, beside whatever its record says of its times. No count of writes. The diff reads the journal segments between the two sequences; when either checkpoint has no `journal_seq`, they are of different watches, or a segment is gone, there is none and the diff's trailer says `touched: "not available"`. Never for a `meta` file: its content is on neither side. Only for files on a filesystem of K2a. Also `not available` when the recorder was not the same process over the whole interval. A file replaced by an equal one (a rename over it) is `touched` too: its inode was written. The set of written inodes is held in a sorted temporary file, under capture-scale SC-M2's bound. | measured: the put-back case gave `M, MW, M, M, W, WA` for two redirections and a `touch`: events are not writes (`round-4/out-fan/fan-cases.log`) |

## What it does not see, and what belay says

| id | case | said as | how established |
|---|---|---|---|
| K14 | a write through a mapping while a descriptor or the mapping lives | closed by K8's look; a file held only by the kernel (a loop device's backing file) is not reachable: `docs/cli.md` says so | measured (E1) |
| K15 | an inode-flag change where `iflags_events` is false | the receipt's `kernel record` line adds `inode flags as of the last walk` | measured (E1, 6.8) |
| K16 | a change beneath the filesystem (block device, snapshot rollback) | not seen until a walk, and then only by its stat; `docs/cli.md` | from knowledge, not run |
| K17 | anything before `watch start`, or while no recorder ran | the first capture after is a walk; `put back` is lost for the gap and the receipt's `kernel record` line gives the gap | measured: a reader started after a change reports nothing (`round-4/out-fan/late-seen.txt`) |
| K18 | who made a change | never said. A pidfd is not requested. | measured: with `FAN_REPORT_PIDFD` the executable was unreadable (`exe=?`) for most short-lived writers (E1, E6) |
| K19 | a root process stopping the recorder or editing the journal | `docs/cli.md`: the on-machine record is of a system that is not fighting it | the review's F17 |

## `--docker`

| id | rule | how established |
|---|---|---|
| K20 | The recorder runs on the host and marks the filesystem that holds the container's upper directory, when it is ext4 (K2a). An event is the container's when its object or directory resolves under that upper directory or its work directory. | measured: create, in-place write, copy-up, chmod, whiteout, remove-and-recreate, rename all give events under `<upper>` and `<work>` on both kernels (E6) |
| K21 | The capture is skipped only when there is no event of the container since the barrier **and** no unresolved event on that filesystem **and** no process in the container's cgroup has a shared writable mapping of a file (`rw-s` in its `maps`). Otherwise: the host reader's ordinary capture (host-reader.md). The journal never decides which entries are carried. When the upper directory's filesystem is not marked (K2a), the capture is always taken. The look at the container's processes also covers descriptors open for writing on a regular file (`/proc/<pid>/fd`), as K8 does on the host. | measured: several overlay events do not resolve (`Stale file handle`) (E6); a mapping written inside a container was not run (the image had no python): **probe owed** |
| K22 | `touched` (K13) for a path whose inode is in the upper layer on both sides. The files Docker mounts over (`etc/hostname`, `etc/hosts`, `etc/resolv.conf`) are `mount` entries and have none. | measured: `? hostname unknown: mount` (`round-2/unprivileged/diff-etc.txt`); host-reader H-M5 |
